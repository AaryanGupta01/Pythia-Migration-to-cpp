# DECISIONS (one line each)

- Runs in WSL Ubuntu (Python 3.14, g++ 15) on this Windows host; native Windows toolchain (MinGW 6.3) cannot build C++17.
- Python package for the backend is `pythia/studio/`; `studio/` holds docs and the web app.
- Splice uses a decorator (`@_pythia_accelerated`) and keeps the original body untouched, so the diff stays small and reversible.
- Compiled modules raise `FallbackError` for inputs they cannot represent faithfully (e.g. non-ASCII str); the shim then runs the original Python.
- Declined (boundary-cost) functions are compiled and benchmarked as a probe only, never spliced, so the decision is backed by a measured number.
- No ANTHROPIC_API_KEY here: offline LLM cache entries are marked `provenance: "authored"` until re-recorded with a real key.
- Frontend `dist/` is committed so the app runs without Node on the evaluator's machine.
- Oracle baseline is 16/17 on CPython 3.14 (t15 message text differs from 3.12); not touched.
- Demo project root is `demo/textlab/` (main.py + package `textlab/`), so fids look like `textlab/text/distance.py::edit_distance`; scale factor 1 for `--small`, 4 otherwise.
- Demo "guarded" vs "verified": expected by D1 (int +,-,* not provable) sites; the global D7 note (line 0) appears on every list/str function and is ignored for that split. Interval analysis elides 0 guards in the demo wins (bounds come from len()/params), so n-body and k-means are the fully exact ones.
- Authored offline rewrites live in `demo/offline_cache/authored_rewrites.json` (keyed by function name, provenance "authored"); `scripts/author_offline_cache.py` converts them to `llm/<key>.json`.
- Web UI (Agent D): `?mock=1` serves the whole API/event stream in-browser (src/mock); the reducer, player and views are identical for mock, live WS and saved-job replay.
- Web UI: events pass through a Player (instant or paced) before the pure reducer, so presenter mode, replay speed and Space/Arrow stepping work for every source.
- Web UI: Monaco is bundled (edcore + python/cpp tokenizers + one worker); fonts via @fontsource; no CDN at runtime.
- Web UI: the diff view shows the whole file (original vs spliced work copy) with unchanged regions folded; a toggle compares the original function to the PySub rewrite.
- (C) Server adds `mock_data.py` (demo project text + per-function outcomes) next to `mock_engine.py`; mock C++/fidelity come from the real front-end (`pythia.cli.compile_source`) when importable, so they are real, not invented.
- (C) Event `seq` starts at 1 and is contiguous per job; the bus (not the engine) writes `events.jsonl`, buffering events emitted before `start_job` returns the job id.
- (C) Mock export is user-triggered (`export.done` after POST /export); pass `options.export=true` to make the scripted stream cover every §4 event type.
- (C) `/api/upload` parses multipart with the stdlib `email` parser (no python-multipart dependency); `/api/stages` falls back to a stdlib tokenize/ast dump flagged `"mock": true` when `pythia.stages` is absent.
- (C) Server answers only requests whose Host header is localhost/127.0.0.1 (DNS-rebinding guard) and binds 127.0.0.1.
- B2: ingest.ingest honours optional input["ws_id"] (one-line edit) so POST /jobs can return workspace_id immediately.
- B2: replay compares dict results order-insensitively; print() side effects inside functions are not compared; measured speedup <0.95 turns a verified function into `declined` (never splice a slowdown).
- B2: rec.sources.pysub = scan.Extract.source (standalone module incl. helpers); rec.build gains additive keys exposed, cpp_path; shim also falls back to Python on TypeError (unmarshallable arg); PYTHIA_ACCEL=0 disables the shim.
- B1: ingest copies project contents to the workspace ROOT (no extra top-level folder), so fids are project-relative and `trace_cmd` is relative to the project root.
- B1: only module-level *scalar* constants (int/float/bool/str/None, simple constant expressions) are inlined into PySub functions; list/dict globals make a function not_eligible (mutation + per-call rebuild cost).
- B1: not_eligible by design: bitwise ops, default parameter values, tuple returns, user classes, module/third-party calls, closures, I/O. Methods are listed as not_eligible ("method of class X"); nested defs are not listed separately.
- B1: any typechecker rejection of otherwise-clean code is `fixable` (LLM may fix), except type rebinding / unknown types / undefined names which are `not_eligible`.
- B1: `Extract.helpers` = names of pulled-in same-module callees; `Extract.uses` = names of inlined constants. Scratch state lives in `rec.private` (`modinfo`, `siblings`, `own`, `fix_kind` = "annotations"|"rewrite").
- B1: ranker declines (net saving < 0 from trace numbers) only verifiable functions and annotation-only fixable ones; rewrite-fixable ones just get a note. Constants MARSHAL_S_PER_ELEM / CALL_OVERHEAD_S in rank.py are the calibration knobs.
- B1: `llm.make_client(model, offline_cache_dir=None, *, offline=None)`: offline defaults to "cache dir given". Fixer sets `rec.rewrites`, and on success `rec.sources["pysub"]` + `line_map_ok=False`. Anthropic calls send no temperature (rejected by newer models).
- Library wrappers use a reusable header `runtime/pyrt_bridge.hpp` (marshalling templates); generated glue stays short. Exporting a module needs `-I runtime` and `runtime/pyrt.cpp`.
- `elide_guards(mod, exposed=...)`: literal-call-site parameter bounds are dropped for exposed functions (they are called from Python with arbitrary ints); default behaviour unchanged.
- Marshalling: int outside int64 -> OverflowError (contract); any other type mismatch (float for int, non-bool for bool, tuple for list, non-ASCII str) -> FallbackError.
- Library builds precompile `pyrt_bridge.hpp` (PCH, ~135 MB per toolchain in the build cache) and cache one `pyrt.cpp` object: cold build ~9 s, further builds ~4 s, cache hit ~20 ms.
- (G) Primary demo is `demo/quanta/` (about 3,800 lines, pure Python, `python main.py --small`); `demo/textlab/` stays as the quick demo. `{kind:"demo", name:"quanta"|"textlab"}` (default quanta) resolves through `pythia/studio/demos.py`, which also feeds `GET /api/demos` and gives each demo its default trace command and time budget (engine raises `trace_timeout_s` to the demo's budget).
- (G) Rank marks "cold" functions (<0.2% of the traced runtime): verifiable ones become `declined` with a "Cold" reason and are not compiled; fixable ones stay `fixable` and get no LLM call. Without this a 270-function project would build ~80 modules and call the LLM on every glue helper that uses an f-string.
- (G) scan.py: a method call or attribute read on a parameter annotated with a non-PySub type (e.g. `rng: Lcg`, `table: Table`) is a hard `not_eligible` ("object of type X"), not "fixable": no rewrite can make an object cross into PySub, and the old rule sent such glue to the LLM.
- (G) Quanta fixable functions avoid float `sum()` on purpose: CPython 3.12+ sums floats with compensated summation, so a loop rewrite would differ in the last bit and (correctly) fail replay. Int sums and explicit float accumulation loops are fine.
- (G) Quanta keeps module-level helper call counts low (the tracer instruments every module-level function call, about 2 us each): hot loops are inlined inside kernels, and the LCG object is a class (methods are not traced).
- (I) Packaging: hatchling wheel; `runtime/`, `studio/web/dist`, `demo/` stay where they are in the checkout and are copied into the wheel via `force-include` (to `pythia/_runtime`, `pythia/studio/web_dist`, `pythia/studio/demo_data`). `pythia/paths.py` is the single resolver (wheel path first, checkout fallback); `tools/oracle.py` still uses `<repo>/runtime` directly.
- (I) `pythia-studio` = `pythia/studio/launcher.py` (doctor banner, single-instance probe via GET /api/doctor, `--app` chromeless window with its own profile dir, closing the window stops the server). `python -m pythia.studio.server` is unchanged.
- (I) PWA manifest, icons and the `<link rel=manifest>` injection are served by the backend (`pythia/studio/branding.py`), so `studio/web` is untouched. Host guard accepts localhost plus `PYTHIA_ALLOWED_HOSTS`.
- (I) Docker image installs the wheel into python:3.12-slim + g++; compose publishes on 127.0.0.1 only. Windows support is via WSL2 (`scripts/install.ps1`), not native.
- Windows is native now: the app bundles a relocatable CPython 3.13 (NuGet) and WinLibs MinGW-w64 GCC 16 (UCRT); extension modules link `-static` against python3X.dll, so a .pyd needs nothing else. WSL stays as a fallback.
- GCC's `%:if-exists(default-manifest.o%s)` spec breaks on install paths with spaces: the bundled toolchain renames the object and PYTHIA passes it explicitly for executables (`toolchain.exe_link_args`).
- The replay worker's per-call timeout uses SIGALRM on POSIX and a timer thread + `_thread.interrupt_main` on Windows.
- PySub 1.1 adds f-strings, `input()`, str/list methods, `format/round/sum/sorted`, n-ary/list `min`/`max`, lists of class instances, `print(sep=, end=)`; the oracle went to 19/19 (t18, t19 added).
- Runtime error texts follow the CPython minor version that runs the comparison (3.11-3.14 word ZeroDivisionError differently); CLI programs get it from the compiling interpreter, extension modules from `PY_MINOR_VERSION`.
- `print(a, f(b))` now evaluates every argument before printing when a later argument contains a call (CPython order); found while writing t18.
- Whole-program AI conversion lives in the Playground (`converter.py`): the type checker judges each answer (<=3 rounds) and Run compares the ORIGINAL under CPython with the compiled conversion on the same stdin.
- First-run setup wizard: doctor checks, live key test (`/api/settings/test-key`, list-models call), `setup_done` in settings.
- Prebuilt modules in demo_data/offline_cache/so are used online as well (keys hash exact source + toolchain, so reuse is sound); the Windows bundle ships Windows builds instead of the Linux ones.
